## 已核实的现状

- 项目为 vinext / Vite / React / TypeScript，Workers 运行时，PostgreSQL 数据库；支付签名应使用现有运行时支持的 Web Crypto，不能照搬依赖 Node 全局环境变量的示例。
- `app/pricing/pricing-content.tsx` 已有会员方案：99 元／30天、新用户体验七天。页面同时出现“无限期畅学”文案，与月卡期限不一致，接入时需要修正。
- 当前弹窗展示的是 `QrCode` 图标，并非可付款二维码；客服号为代码中的固定值，尚未核实。
- `app/api/pricing/apply/route.ts` 主要写日志、可能更新联系信息，没有支付订单与交付记录；前端忽略请求失败后也展示申请成功。该接口不能作为支付确认依据。
- 现有权限使用 `users.trial_ends_at`：NULL 表示长期权限。没有独立的付费到期字段，不能直接以“付费则清空体验期限”实现月卡。
- 已检查本地 `.dev.vars`、`.env.local`、`.env.postgres`、`.deploy.vars` 的配置名称，均无支付配置；未读取或输出凭据值。进程环境中是否另行注入支付配置尚未核实。
- 2026年11月3日 18:17:28（北京时间）核查期间向指南规定的创建接口发送空 JSON 探测，返回 HTTP 503。没有创建支付订单，没有进行扣款。

| 固定付款返回地址 | 未确认 | 建议 `https://study.chumenclub.com/payment/result`；本地联调用获准的隧道返回地址 |
| 本地可接收公网 HTTPS 回调 | 未提供隧道 | localhost 无法直接接收支付服务器回调；配置隧道并限制转发到本项目端口 |
| 移动端需求 | 待确认 | 指南当前仅支持电脑网站支付；手机唤起需支付侧另行支持 |

业务站不需要支付宝应用私钥、公钥或额外支付宝 API Key。核心凭据是双方共享密钥，且需要与已登记 source、回调及返回地址一致。不要把密钥发到聊天正文或写入公开文件。

本地 `.dev.vars` 所需项目（占位说明，不能直接用于支付）：

```dotenv
PAYMENT_GATEWAY_URL=https://skills.chumenclub.com/api/cross-site-payment/create
PAYMENT_SOURCE=由维护者确认的拾题来源
PAYMENT_SHARED_SECRET=由维护者安全提供
PAYMENT_RETURN_URL=https://已登记的本地隧道域名/payment/result
```

回调地址由支付服务器配置，不是当前下单协议中的请求字段。

## 条件满足后的实施范围

- REQ-PAY-001：沿用 99 元／30天月卡；后端商品配置确定价格，前端不能传入最终金额。真实 0.10 元联调使用仅测试范围可用的独立商品，不能将正式月卡随意降价。
- REQ-PAY-002：追加 PostgreSQL 迁移，保存订单号、用户、商品快照、金额整数分、来源快照、网关订单号、支付与交付状态、付款时间、通知事件；为订单与网关映射添加唯一约束，保留财务记录与账号删除的处理规则需在技术方案中明确。
- REQ-PAY-003：登录与同源校验后创建订单；调用网关并绑定 localOrderId，超时使用同一订单重试。回调早到时先持久保存待核对事件，绑定后在事务中处理，不能只靠内存等待。
- REQ-PAY-004：按指南原字段顺序执行 HMAC-SHA256 / 标准 Base64；回调先验原始金额字符串签名和五分钟时间窗，再核对金额、订单和可信网关映射。错误请求返回非 2xx，数据库错误不伪装成功。
- REQ-PAY-005：订单锁、唯一交付记录与用户行锁确保重复或并发回调只开通一次；独立保存付费到期时间。30天从当前时间、有效体验到期时间及有效付费到期时间中的较晚者计算；已有长期权限保留并禁止无意义购买。此规则为拟定方案，实施前确认。
- REQ-PAY-006：会员页进入收银页，展示账号、商品、金额、权益、付款按钮与失败重试；仅跳转 HTTPS 且主机严格为 openapi.alipay.com 的 URL，不展示占位收款码。
- REQ-PAY-007：返回页仅轮询当前用户自己的本地订单；返回参数不能变更付款状态。确认超时显示待确认，不自动变成失败；提供订单历史便于付款后关页再查看。
- REQ-PAY-008：AI 服务端权限及各页面状态统一支持付费期限。历史数据读取继续可用；管理员和已有长期账号权限保留。
- REQ-PAY-009：未配置或网关不可用时明确提示不可付款；退款、手机唤起及主动查网关订单均不假设存在未提供的接口。

## 本地验收

1. 在真实 PostgreSQL 独立测试 schema 验证迁移、事务与订单持久化，不伪造支付成功。
2. 验证匿名／越权／跨源下单被拒、金额不可篡改、支付链接目标限制。
3. 验证错误签名、过期通知、错误金额、映射冲突、重复与并发通知、通知早到、下单超时重试。
4. 可使用测试密钥在隔离环境验证协议，但必须标为协议测试，不能作为真实付款验收；不得用模拟网关冒充真实支付跑通。
5. 构建、类型检查、相关检查通过后，浏览器验证收银、失败状态、返回页、订单刷新恢复。
6. 支付维护者开放后，使用获准的 0.10 元订单，由用户实际付款，核对网关收款、两段通知、数据库订单与权益仅交付一次。
7. 关闭浏览器后仍能由后端确认；重启后订单与通知记录保留。完成这些证据才能声明本地真实支付闭环通过。
