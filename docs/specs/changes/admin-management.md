# 后台管理流程完善

适用页面：`/admin`，面向管理拾题账号和学习内容的管理员。沿用现有浅色、蓝紫色主操作、侧栏导航与紧凑表格，管理操作优先保证可查找、可理解和可恢复。

## 页面与操作

- 用 `tab` 查询参数保存后台栏目，浏览器前进、后退和刷新可以恢复栏目。
- 支持 `userId`、`uploadId`、`subject` 管理链接，从用户进入其错题，从上传批次进入关联错题，从学科分布进入学科筛选。
- 用户列表提供体验中、体验已到期、长期可用筛选，以及注册时间、最近登录、错题数量排序。
- 学科选项包含数据库已有名称，保留原始学科数据，避免已有分类无法查询。
- 账号删除确认列出清理范围，并要求输入用户名；当前管理员继续禁止停用、删除及降级自己。
- 查询切换取消过期请求，提供加载结构、空结果说明和错误重试；提升辅助文字对比度与表格可读性。

## 数据一致性

- 账号、上传、错题、练习卷、知识点和作文报告保存到 PostgreSQL，使用标准 `pg` Pool、参数化 SQL 与真实事务。标识使用 text，时间使用 timestamptz，结构化字段使用 jsonb，接口保持 ISO 时间及现有 JSON 内容。
- 用户资料、密码、状态与权限在事务内通过单次 UPDATE 提交。体验延期根据数据库执行时的期限计算；长期权限不会被旧的延期请求覆盖。
- 修改账号及删除账号先获取共用事务 advisory lock，再锁定目标账号，保护最后一个启用管理员，并禁止修改已开始删除的账号。
- 六张业务表的 INSERT、UPDATE 触发器使用 `FOR SHARE` 锁定所属账号并检查启用状态及删除标记，使已开始的 AI 请求保存与账号停用形成确定的执行顺序。
- 错题通过 `(upload_id, user_id)` 复合外键关联上传批次，禁止跨账号关联。
- 图片内容上传前持久保存 R2 multipart 标识。删除账号先停用并使原有会话失效，再终止全部已登记上传、严格读取图片索引，去重后每组最多删除 1000 个对象，最后通过事务清理数据库。清理失败保留账号和索引以便重试，请求进程中断后仍可继续清理。
- 错题、上传分页使用创建时间和唯一 ID 排序。

## 验证范围

使用已有本地管理员与普通账号进行真实 HTTP 和浏览器验证，不使用 mock 或新增示例业务数据。验证结果记录在交付文档中。线上仅进行只读页面检查，发布需另外授权。
