## 结论

**部分实现，不足以认定整段需求完成。** 已归档错题的按天汇总、本人错因、选题排序、Word 剪贴模板有实现；从拍好的已批改试卷到可打印错题仍缺人工选题/确认入口。网页修改题干和多孩档案未实现；原图字小的诉求没有被正文字号选项完整解决。

## Findings（按影响排序）

### [P1] 自动判题是唯一归档入口，无法完成“把老师判错的题整理打印”

代码：`lib/ai.ts:237`、`lib/uploads.ts:89`、`app/upload-record.tsx:6`、`app/dashboard.tsx:669`。

触发：一张有教师批改、图形或低置信度文字的作业照片。当前逻辑只要检测到题目含配图，或题目/任一相关元素置信度低于 0.8，就强制改为 uncertain；数据库仅为最终 incorrect 的项目建立 mistakes。详情提供原图、文字展示和有限的重试，没有“选中本题是错题”“确认文字后归档”或“仅原图归档”的写入口。打印只接受已存在的 Mistake。

结果：即使家长明确知道哪题错，仍无法把该题放进当日错题集合、填写错因和批量打印。这会直接阻断截图里最重要的使用场景。此前真实照片 3/8 题全部待核对的实测与该路径一致，但本轮结论以源码调用关系为据。

建议：补人工确认/圈选归档，保留原题与判定来源，不能靠调低阈值绕过。对已批改作业允许不调用 AI 判题直接整理；复杂图形允许保留图片。归档需权限、版本与唯一性约束。

### [P2] 原图文字不会随 12/14pt 放大，长图仍可能缩到难以剪贴阅读

代码：`lib/mistake-docx.ts:140`、`lib/mistake-docx.ts:180`、`lib/mistake-docx.ts:267`、`lib/word-source.ts:39`、`app/dashboard.tsx:684`。

正文字号只应用于 OOXML 文本样式；图片使用固定最大宽高按比例缩放，没有绑定字体设置。剪贴长图超过最大高时仍适配为单张图片，代码本身也输出“图内字号可能偏小”。旧题无可用题框会携带整页原图；服务端读取原图也始终返回 fullPage=true。即使前端新题剪贴路径可裁剪，旧记录/长题依然存在缩小风险。

结果：用户选“大字”后，题干文本变大，但必须保留的原图公式、图表、作答仍可能很小；整页还可能重复包含其他题。不能把“有 14pt 设置”当成截图中“解决原题打印字太小、浪费纸”的完成证据。

建议：增加题框确认/手动裁剪、打印图片尺寸与分页预览；长图允许分段或调整物理尺寸；对图内字号不受设置影响作明确提示。需用真实 Word/WPS 和普通打印机验收，不能只验证 ZIP/XML。

## “编辑”和“日期”的需求解释

截图中的“再编辑”没有明确限定编辑字段。之前的正式范围将其解释为选题、顺序、错因和打印设置，该窄范围已有实现；若按用户可能期望的“在网页修正识错的题干”理解则没有完成。不能用现有规格的窄定义宣称满足截图里的所有编辑诉求。

日期已有规格采用北京时间“归档完成日”。因此这不是已确认规格内的日期计算 bug；但“选择我当天拍的试卷”需要上传日期/批次筛选，不能与归档日期混称。补传、隔天重试的题可能显示在实际归档日，需明确显示来源和日期类型。

## 多孩的决策边界

截图明确有人提出多孩，也有人认为一个孩子一个账号。当前代码与历史规格都没有落实多孩，只能给出“未实现/商业方案待定”。本轮不据聊天中任意一方意见创建档案或调整价格。

若后续选择多孩，必须同时覆盖上传、题目、错题、反思、打印抬头、练习、作文、知识点和权益，不能只增加一个下拉框。切换孩子后未保存草稿与后台任务的归属也要固定。

## 建议补齐顺序

1. 人工圈选/核对归档，让已知错题能真正进入错因与打印流程。
