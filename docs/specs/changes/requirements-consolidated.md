# 拾题需求总清单与开发范围

> 实施更新：用户已授权开始全量开发。下文“当前状态”按本地代码与验证更新；逐项证据及未完成实物验收见[全量实施与验证](../../delivery/features/requirements-implementation.md)。生产尚未更新。

## 1. 本轮任务与结论

用户要求：把群聊截图需求、使用流程问题和功能重构方案统一整理为文档，先汇报哪些没有实现，再进行开发。**本轮已按需求基线完成本地编码与排错，未执行提交、推送、生产迁移或发布。真实资料隔离验证、Workers和浏览器证据另见实施记录，纸面/作文等未验收项明确保留。** 后续开发以本清单的编号追踪；开发授权不包含自动提交、推送、生产迁移或发布。

结论：已有的存储、识别、历史恢复、错因和 Word 导出需要保留。本轮已补齐人工核对确认、手动归档、按上传批次整理、原图尺寸与分段、多孩服务端隔离，以及订正与复练版本记录。

“全部需求”包含两类来源，不能混成用户已经逐条指定的设计：

- **原始需求及明确反馈**：截图中的原题保真、按时间选试卷、汇总错题、自己的错因、编辑与剪贴打印、多孩；本次使用中的刷新丢失和历史缺失。
- **为完成流程提出的设计**：三种上传意图、题目版本、状态分离、新导航、复习安排、作文修改稿等。用户已要求整理并开发，纳入分阶段范围；其中具体默认值为本文件的实施建议，不冒充现有产品行为。

## 4. 第一批必须打通的主流程

```mermaid
flowchart LR
  A[上传试卷并保存] --> B[百度识别与切题]
  B --> C[核对文字和题框]
  C --> D{这次要做什么}
  D -->|老师已判错或收藏| E[人工确认选题归档]
  D -->|检查未批改作业| F[分析确认后的题目]
  F --> E
  E --> G[多选作业汇总]
  G --> H[填写自己的错因]
  H --> I[裁剪与排版预览]
  I --> J[导出Word并打印剪贴]
```

每个节点必须保留可恢复的保存点；待核对不算全对，处理完成不等于学习完成。对于老师已判错的题，人工确认归档、编辑和打印不需要先成功调用 AI 判题。

## 6. 状态、数据和接口约束

1. 账号是登录与权益主体，孩子是学习资料归属主体；旧账号资料迁入一个默认档案，不破坏现有账号、密码、图片键和内容。
2. 作业、题目、确认版本、分析结果、归档关系和练习轮次分别表达，不让一个 `completed` 代表所有事情。
3. OCR 原文只读保存；用户编辑写确认版本，模型只分析明确的输入版本。低置信度/图形无法判断时允许人工处理，不允许模型猜题冒充原文。
4. 手动归档与模型建议分开标记；空白题/不会做可收藏，不默认判错；缺解析不应阻止保存原题和打印。
5. 已保存历史、用户文字编辑、错因、选题与打印不触发外部 AI 调用；识别、分析和出题按钮明确处理范围。
6. 题目修改后旧报告保留并标记过期；已确认错因不随重新分析被覆盖。
7. 附件、数据查询与导出都执行服务端权限校验；切换档案不能只做客户端筛选；存储对象和运行中任务固定所属档案。
8. 数据结构只能追加正式迁移；实际执行前备份，验证旧 ID、原图、反思与练习不丢失。

## 7. 验收清单

- 用真实图片验证两份已批改试卷：手动选择已知错题、改正识别文字、裁剪题图、合并打印，全程无需 AI 再判错。
- 用真实未批改作业验证确认后分析、待核对恢复和正确/错误/未知区分；不以接口 200 代替内容验收。
- 上传/编辑/归档/选题/导出各阶段刷新、重登、断网重试和服务重启，已经保存的内容可找回。
- 连续点击或重复请求不能生成多份相同归档；两次练习却必须各自保留作答。
- 两个真实档案的错题、图片、打印、练习、作文与统计互不混入；其他账号仍不可访问。
- DOCX 结构、真实 Word/WPS 分页和实际 A4 打印分别记录；12/14pt 文字与原图可读尺寸分别检查。
- 一份含配图或低置信度题的作业，不再只能停在“待核对”无下一步。
- 旧记录和新记录同时可读；旧版报告缺失明确说明，不能补造。
